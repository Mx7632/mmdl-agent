## 3. 压缩后的章节大纲

### 第 1 章 绪论

1.1 研究背景与意义
1.2 国内外研究现状
1.3 现有方法存在的问题
1.4 本文主要工作
1.5 论文组织结构

写作重点：说明工业异常检测为什么需要“定位、解释、追问和知识辅助”，不要夸大系统性能。PatchCore、多模态大模型、RAG、多 Agent 作为技术路线引出即可。

### 第 2 章 相关技术与需求分析

2.1 工业异常检测与 PatchCore 方法
2.2 多模态大模型与 MMAD 任务思想
2.3 RAG 与少样本上下文构造
2.4 多 Agent 协作与 LangGraph 编排
2.5 系统应用场景与功能需求
2.6 非功能需求与本章小结

写作重点：把原第二章“相关技术”和原第三章“需求分析”合并。角色描述应写成使用场景角色，如检测人员、技术人员、维护人员，而不是系统账号权限模型。

### 第 3 章 系统总体设计

3.1 系统总体架构
3.2 用户交互层与 API 任务运行层
3.3 图编排层与多 Agent 协作层
3.4 工具、知识与状态记忆层
3.5 主运行流程设计
3.6 可扩展性与异常处理设计

写作重点：这里回答“系统分成哪些层，每层负责什么”。推荐使用分层架构：用户交互层、API 与任务运行层、图编排层、多 Agent 协作层、工具与知识层、状态记忆层。不要引入项目没有实现的多租户、安全中心、CI/CD 平台等平台化能力。

### 第 4 章 系统详细设计与实现

4.1 API 接口与任务模型实现
4.2 Supervisor 与多 Agent 节点实现
4.3 视觉检测模块与 PatchCore 热力图实现
4.4 RAG 知识库与 Few-shot 上下文实现
4.5 状态记忆、追问续接与报告生成实现
4.6 前端交互与可视化实现

写作重点：这一章要落到代码。每节都应写“输入是什么、核心处理是什么、输出是什么、对应代码在哪里”。避免大段抽象叙述。

### 第 5 章 系统测试与实验分析

5.1 测试环境与数据来源
5.2 接口与前端功能测试
5.3 PatchCore 异常定位实验
5.4 RAG 检索与少样本上下文实验
5.5 多 Agent 流程与追问链路测试
5.6 测试结果分析与问题讨论

写作重点：只写真实运行过、能复现的实验。可以设计功能测试表、接口测试表、PatchCore 正常/异常样本对比、RAG 检索结果检查、多 Agent 时间线观察。不要编造准确率、召回率、吞吐量或用户规模。

### 第 6 章 总结与展望

6.1 本文工作总结
6.2 系统实现效果
6.3 当前不足
6.4 后续优化方向
6.5 本章小结

写作重点：总结要对应前文工作，不要新增未实现功能。展望可以写阈值标定、更多类别评估、知识库质量提升、模型微调、在线反馈闭环等，但必须明确为后续工作。

## 7. 第五章实验可执行设计

- 功能测试：使用 `/health`、`/v1/stream`、`/v1/rag/build/start`、`/v1/rag/build/status/{task_id}`、`/v1/rag/query`、`/v1/patchcore/categories` 等接口验证主链路。
- 前端测试：验证开始检测、继续追问、RAG 构建、RAG 查询、PatchCore 热力图展示、多 Agent 时间线渲染是否正常。
- PatchCore 实验：选择 MVTec 中已训练类别，例如 bottle；分别使用 good 和 defective 样本，记录阈值、输出区域、是否误报。不要只用单张图下结论。
- RAG 实验：先构建知识库，再输入与产品、缺陷、风险相关的问题，检查是否能返回相似案例和 few-shot 元数据。
- 多 Agent 实验：准备正常图、异常图、信息不足图三类任务，观察 Supervisor 是否触发 VisionAgent、KnowledgeAgent、ClarificationAgent、ReportAgent 等节点。
- 追问链路实验：首轮检测后提出原因、是否使用 RAG、重新分析等追问，验证上下文是否续接而不是重复旧答案。

## 8. 后续给 Composer 的 Handoff

### 8.1 文档处理顺序

1. 复制学校模板/当前草稿 DOCX，生成工作稿，保护原文件。
2. 保留封面、诚信承诺书、使用授权书、摘要页、目录页、参考文献页、致谢页的学校格式。

4. 将正文调整为 6 章结构，删除旧第三章独立编号，将需求分析合并进新第二章。
5. 将旧第四章压缩为新第三章，将旧第五章改写为新第四章。
6. 根据真实运行截图和测试记录补写第五章，最后更新第六章总结。
